For refinement mode, create a SECOND useGenStream instance for chat:
```typescript
const chatStream = useGenStream({
  api: "/api/gen/chat",
  onComplete: (refinedSpec, rawLines) => {
    // Update the active spec in the database by saving as new entry
    // (refinement overwrites — save the refined version)
    void saveSpec({ prompt: `Refined: ${promptRef.current}`, spec: refinedSpec, rawLines });
  },
});
```

Wait — the `/api/gen/chat` endpoint expects a `messages` array, not `{ prompt }`. The useGenStream hook sends `{ prompt, context }` in the body. This won't match the chat endpoint's expected schema.

**Solution**: Instead of a second useGenStream instance, create a dedicated `sendRefinement` function that:
1. Builds the messages array: first message is an assistant message with the current spec JSON (`"Here is the current spec: " + JSON.stringify(currentSpec)`), then appends all accumulated chat messages, then the new user message.
2. Calls fetch directly to `/api/gen/chat` with `{ messages }` body and auth header.
3. Reads the streaming response (similar to useGenStream's internal logic but simpler — the chat response is text+JSONL, and we need to extract the JSONL patches).

Actually, looking at gen-chat.ts more carefully — it returns `result.toUIMessageStream()` which is an AI SDK UI message stream format, NOT the flat JSONL patches that gen-ui returns. The chat endpoint returns free-form text interleaved with potential spec patches.

**Revised approach for refinement**: The simplest path that works with the existing architecture:
1. When user enters refinement mode, construct a system message that includes the current spec as context.
2. Send to `/api/gen/ui` (NOT `/api/gen/chat`) with the refinement prompt + spec context embedded in the prompt itself: e.g., `"Given the following existing UI spec:\n${JSON.stringify(currentSpec)}\n\nPlease modify it: ${userRefinement}"`.
3. This reuses the exact same streaming JSONL pipeline — no new parsing needed.
4. The result replaces the existing spec entirely (as stated in CONTEXT.md: "each refinement overwrites the stored spec").

This approach:
- Uses the existing useGenStream hook with api="/api/gen/ui" (same endpoint for both modes)
- No need to parse a different response format
- The AI model sees the existing spec and applies the modification
- Simpler to implement and maintain

Implementation in PlaygroundPage:

Output the COMPLETE modified spec (not just the changes).\n\nExisting spec:\n${JSON.stringify(currentSpec)}\n\nModification requested: ${prompt}"`

- When a refinement completes (onComplete), auto-save the refined spec (overwriting by creating a new entry) and set it as active.
