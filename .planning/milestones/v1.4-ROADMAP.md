# Roadmap: Milestone v1.4 - Agentic Orchestration & Observability

**Milestone Goal:** Establish high-autonomy execution loops and deep performance visibility to transition from "AI as a chatbot" to "AI as a deterministic compiler."

## Phases

### Phase 32: The Ralph Wiggum Loop (`mbe loop`)
**Goal**: Build a CLI command that enables autonomous, brute-force iteration for mechanical tasks (e.g., mass refactoring, fixing hundreds of lint errors).
**Success Criteria**:
  1. `mbe loop "Fix all lint errors in services/users"` runs continuously until success or exit signal.
  2. The loop automatically restarts the agent process on failure, preventing "context rot."
  3. The command uses a `TASKS.md` or `STATE.md` file as its source of truth for persistent memory across loop iterations.

### Phase 33: RIPER Workflow Integration
**Goal**: Implement Tony Narlock's "Research, Innovate, Plan, Execute, Review" cycle into our agentic mandates.
**Success Criteria**:
  1. `AGENTS.md` updated with RIPER phase instructions.
  2. Agents are prohibited from editing files until the "Plan" phase is documented and verified.
  3. A `/riper` alias or equivalent exists to transition between phases.

### Phase 34: Automated Rule Synchronizer (Rulesync)
**Goal**: Ensure all AI tools (Cursor, Gemini, Claude) use identical, up-to-date guidelines by generating tool-specific rules from `AGENTS.md`.
**Success Criteria**:
  1. A script `mbe sync-rules` generates `.cursorrules`, `.clauderc`, and updates `GEMINI.md`.
  2. Rule synchronization is added to the `pre-commit` hook or CI.
  3. No manual editing of `.cursorrules` or `GEMINI.md` is required.

### Phase 35: Agentic Observability & Usage Dashboard
**Goal**: Track the cost, success rate, and reasoning paths of autonomous loops to measure ROI and identify failure patterns.
**Success Criteria**:
  1. Agent sessions log token usage, cost (USD), and success/failure status to `docs/logs/agent-traces.json`.
  2. A lightweight CLI command `mbe stats` reports on agent performance over time.
  3. Context "health" (token density vs. hallucination rate) is monitored for long-running loops.

### Phase 36: Parallel Wave Orchestrator (`mbe wave`)
**Goal**: Coordinate multiple sub-agents working in parallel git worktrees to execute independent tasks from a single roadmap.
**Success Criteria**:
  1. `mbe wave "Refactor all service endpoints"` spawns 3+ parallel agents into `.agent-worktrees/`.
  2. The orchestrator monitors all worktrees and merges successful changes back to `main` sequentially.
  3. Atomic commits are maintained for each worktree's contribution.

### Phase 37: Automated Performance Auditor (`mbe audit-perf`)
**Goal**: Automatically analyze agent performance logs and suggest process optimizations (context packing, lint rules, ADRs).
**Success Criteria**:
  1. `mbe audit-perf` CLI command analyzes `agent-perf.jsonl`.
  2. The command identifies "inefficiency hotspots" (high turns, low success).
  3. The command outputs actionable tasks (e.g., "Optimize context for services/reservations").

### Phase 38: The Context Guard (Autonomous JIT Context)
**Goal**: Ensure `llms.txt` files are always up-to-date by triggering `mbe pack` via git hooks.
**Success Criteria**:
  1. A `post-commit` hook automatically identifies changed directories and runs `mbe pack`.
  2. A `post-checkout` hook ensures the local context matches the current branch.
  3. Agents never encounter stale context after a branch switch or merge.

### Phase 39: Structured Architecture Decision Records (ADRs)
**Goal**: Transition ADRs to a machine-readable format to enable automated architectural linting.
**Success Criteria**:
  1. ADRs use a standardized YAML/Markdown format in `docs/adr/`.
  2. A new CLI command `mbe check-adr` validates code changes against active ADRs.
  3. The system automatically alerts agents if a proposed change violates a settled architectural decision.

### Phase 40: Model Governance & Verification (`mbe check-model`)
**Goal**: Ensure the most cost-effective and capable model is used for every task by implementing dry-run verification and explicit governance rules.
**Success Criteria**:
  1. CLI command `mbe check-model "<directive>"` dry-runs the model selection logic.
  2. Log schema includes `modelId` to track model-specific success rates.
  3. `AGENTS.md` contains a "Model Governance" section with tier definitions.
