  <action>
1. First verify the agent service is deployed and reachable:
   ```bash
   curl -s -o /dev/null -w "%{http_code}" https://api.mattbutlerengineering.com/health
   ```
   Expected: 200. If not 200, the deployment from Plan 02 may not be complete — check `doctl apps list` and deployment status.

2. Verify auth rejection (GEN-03):
   ```bash
   curl -s -w "\n%{http_code}" https://mattbutlerengineering.com/api/gen/ui
   ```
   Expected: 401

3. Obtain a valid Auth0 JWT for testing. Use the existing CLI or auth flow:
   ```bash
   # Option A: Use mbe CLI if it has auth
   mbe auth token 2>/dev/null
   # Option B: Use curl with Auth0 client credentials or password grant
   ```
   If no automated token retrieval is available, this becomes a checkpoint step — note in SUMMARY.

4. Verify SSE streaming (GEN-07) — the critical test:
   ```bash
   curl -N -H "Authorization: Bearer <TOKEN>" \
     -H "Content-Type: application/json" \
     -d '{"prompt":"a simple card with a title and subtitle"}' \
     https://mattbutlerengineering.com/api/gen/ui 2>&1 | head -20
   ```
   - `-N` disables curl buffering
   - Output should arrive in multiple chunks progressively (not all at once)
   - The response should contain SSE-formatted data lines
   - Check that `x-vercel-ai-ui-message-stream: v1` header is present in response

5. Verify prompt caching (GEN-05) — send the same request twice:
   ```bash
   # First request — creates cache
   curl -N -H "Authorization: Bearer <TOKEN>" \
     -H "Content-Type: application/json" \
     -d '{"prompt":"a simple card"}' \
     https://mattbutlerengineering.com/api/gen/ui > /dev/null 2>&1

   # Second request — should hit cache
   curl -N -H "Authorization: Bearer <TOKEN>" \
     -H "Content-Type: application/json" \
     -d '{"prompt":"a simple button"}' \
     https://mattbutlerengineering.com/api/gen/ui > /dev/null 2>&1
   ```
   Then check agent service logs for the second request:
   ```bash
   doctl apps logs <APP_ID> --component agent-api --tail 20 2>/dev/null | grep "gen cost log"
   ```
   Expected: `cacheReadInputTokens > 0` in the second request's log entry.

6. If SSE is buffered (one big response instead of chunks), check:
   - `X-Accel-Buffering: no` header is being set by Fastify
   - Edge router is returning `fetch()` response directly for `/api/*` paths
   - No intermediate proxy (Cloudflare orange-cloud on api subdomain) is buffering
