<objective>
Create the client-side registry that maps catalog component type names to actual Rialto React component implementations.

Purpose: The registry is the bridge between the AI-generated JSON spec and rendered Rialto components. When json-render's Renderer receives a spec with `{ type: "Card", props: { title: "Hello" } }`, the registry tells it to render `<Card title="Hello" />` from @mbe/rialto. This is the client-side half of the catalog/registry split -- catalog stays server-side, registry ships to the browser.

Output: `registry.tsx` with defineRegistry() covering all ~25 curated components, exported from index.ts, with tests.
</objective>

```typescript
import { defineRegistry } from "@json-render/react";
import { Button, Card, Input, Text, Stack, Badge, Alert } from "@mbe/rialto";
import { catalog } from "./catalog.js";

export const { registry } = defineRegistry(catalog, {
  components: {
    Button: ({ props, emit }) => (
      <Button
        variant={props.variant}
        size={props.size}
        disabled={props.disabled}
        onClick={() => emit("press")}
      >
        {props.children ?? props.label}
      </Button>
    ),
    Card: ({ props, children }) => (
      <Card title={props.title} subtitle={props.subtitle} padding={props.padding}>
        {children}
      </Card>
    ),
  },
});
```

// Card: variant, padding, title, subtitle, children
// Stack: direction, gap, align, justify, children

// Toggle: label, checked, onCheckedChange, disabled
// Dialog: open, onClose, title, children

- **Simple prop forwarding:** Most components just spread props and pass children. Example: `Card: ({ props, children }) => <Card {...props}>{children}</Card>`.
