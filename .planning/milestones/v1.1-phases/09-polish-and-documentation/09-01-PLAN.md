  <action>
Create `packages/rialto/docs/manual-a11y-checklist.md` with step-by-step manual testing instructions for Dialog, DropdownMenu, CommandPalette, and Toast — covering behaviors that axe-core cannot detect.

Format for each component section:
1. **Setup** — exact URL to navigate to and starting state
2. **Checklist** — checkboxes for each behavior to verify manually with a real screen reader

Use these URLs (local dev, localhost:3000 base):
- Dialog: `http://localhost:3000/rialto/overlays/dialog`
- DropdownMenu: `http://localhost:3000/rialto/overlays/dropdown-menu`
- CommandPalette: `http://localhost:3000/rialto/overlays/command-palette`
- Toast: `http://localhost:3000/rialto/feedback/toast`

**Dialog checklist items:**
- Press Enter on trigger — dialog appears
- Screen reader announces dialog title on open
- Tab cycles through interactive elements without escaping dialog
- Shift+Tab wraps back to last element from first
- Press Escape — dialog closes
- Focus returns to trigger button after close (not to body/top of page)
- Click outside dialog — dialog closes; focus returns to trigger

**DropdownMenu checklist items:**
- Press Enter/Space on trigger — menu opens
- Screen reader announces menu role
- Arrow Down/Up navigate items with announcement
- Arrow keys wrap from last to first (and vice versa)
- Enter/Space selects item and closes menu
- Escape closes menu without selection
- Focus returns to trigger after close
- Keyboard shortcuts displayed are announced alongside item labels

**CommandPalette checklist items:**
- Cmd+K opens the palette
- Screen reader announces combobox role and search input
- Typing filters results; result count announced via live region
- Arrow Down/Up navigate filtered results with announcement
- Enter selects highlighted command
- Escape closes palette
- Focus returns to previous element after close

**Toast checklist items:**
- Trigger a default toast — polite announcement (does not interrupt)
- Trigger an error toast — assertive announcement (interrupts current reading)
- Toast title is the announced content
- Toast dismiss button is tab-reachable but focus does not auto-move to toast
- Multiple toasts announced in order of appearance
- aria-live region exists in DOM before first toast fires (verify in DevTools: both polite and assertive regions present at page load)

Include a header explaining these tests require VoiceOver on macOS or NVDA on Windows, and that axe-core cannot verify these runtime behaviors.
