# Phase 22, Plan 1: Service-Level LLM Context (The Repomix Packer)

**Goal**: Expose the entire API surface of our backend services to AI agents via automated, XML-formatted `llms.txt` context files, eliminating the need for expensive recursive file searches during development.

**Dependencies**: None.

## Requirements
- **REQ-22-01:** A new CLI command `mbe pack <service>` must exist in `tools/cli`.
- **REQ-22-02:** The command must parse the target service's Zod schemas, Prisma models (if applicable), and routing files (Hono/Express) into an Abstract Syntax Tree (AST) representation, omitting function body implementations (semantic compression).
- **REQ-22-03:** The output must be written to `<service>/llms.txt` formatted using hierarchical XML tags (e.g., `<file path="..."><interface name="...">...</interface></file>`) optimized for Claude and Gemini.
- **REQ-22-04:** The script must automatically exclude `.env` variables, credentials, and `node_modules`.

## Execution Steps
1. **[TDD] Scaffold the CLI Command:** In `tools/cli`, write a failing test for a generic `mbe pack` command runner. Implement the commander scaffolding.
2. **[TDD] AST Parser Logic:** Write tests for parsing a TypeScript file into a skeleton representation (stripping function bodies but preserving signatures and JSDoc). Implement the parser using `ts-morph` or `typescript` compiler API.
3. **[TDD] XML Generator:** Write tests for converting the parsed AST elements into the Repomix-style XML format. Implement the formatting logic.
4. **Integration:** Wire the `pack` command to output to `services/<target>/llms.txt`.
5. **Verification:** Run `mbe pack users` and verify the output contains the `User` schema and routes, but no implementation logic.

## Verification
- Verify the `pnpm build` and `pnpm test` pass.
- Verify `services/users/llms.txt` is successfully generated and uses XML formatting.
