# Phase 28, Plan 1: Strict Internal Zod Schema Enforcement

**Goal**: Prevent silent failures and AI hallucinations across internal service boundaries by enforcing strict, runtime Zod validation on all inter-service HTTP calls.

**Dependencies**: None.

## Requirements
- **REQ-28-01:** Establish a shared `@mbe/service-schemas` package (or utilize the existing `packages/types`) to house the definitive Zod schemas for all backend microservices (e.g., User schemas, Reservation schemas).
- **REQ-28-02:** All cross-service HTTP clients (e.g., `services/agent` calling `services/reservations`) must be updated to pipe the `Response.json()` through a `.parse()` or `.safeParse()` using the imported Zod schema.
- **REQ-28-03:** Add a CI "Contract Drift" test suite that programmatically verifies that the schemas defined in `@mbe/service-schemas` match the actual output of the backend services in a local mock environment.

## Execution Steps
1. **[TDD] Shared Schemas:** In `packages/types` (or a new package), write failing tests asserting the presence of `UserSchema` and `ReservationSchema`. Implement the Zod definitions based on the Prisma models.
2. **[TDD] Client Validation:** Identify all cross-service fetches (using `grep_search`). For each, write a failing mock test simulating a malformed response. Update the fetch implementation to `.parse()` the payload, passing the test.
3. **[TDD] Contract Tests:** Write a suite in `scripts/` or `e2e/` that hits the local `users` and `reservations` API endpoints with mock data and asserts the responses validate against the shared Zod schemas.
4. **Integration:** Ensure `pnpm typecheck` and the new contract tests run in `ci.yml`.

## Verification
- All cross-service fetch calls strictly enforce Zod validation at runtime.
- Contract drift tests pass successfully.
