# Phase 27, Plan 1: Custom ESLint AST Rules for Architecture Enforcement

**Goal**: Automatically enforce project-specific architectural patterns using ESLint AST parsing, preventing AI agents (and humans) from committing code that violates the "Golden Path."

**Dependencies**: None.

## Requirements
- **REQ-27-01:** Configure `eslint-plugin-local-rules` (or similar workspace-local ESLint plugin) in the monorepo root.
- **REQ-27-02:** Implement rule `no-tailwind-classes`: Statically analyze TSX/JSX `className` attributes and fail if utility classes matching Tailwind patterns (e.g., `flex`, `mt-4`, `text-center`) are detected, enforcing the use of `@mbe/rialto` CSS Modules.
- **REQ-27-03:** Implement rule `require-rfc-7807-errors`: Analyze backend route files (`services/**/routes/*.ts`) and fail if a 4xx/5xx response is returned without using the standard `ProblemDetails` schema structure.
- **REQ-27-04:** Both rules must run during standard `pnpm lint` and block the CI pipeline if violated.

## Execution Steps
1. **[TDD] Plugin Setup:** Create a local ESLint package or configure the existing setup to support custom rules. Write a failing test for a dummy rule, then make it pass.
2. **[TDD] Tailwind Rule:** Write failing test cases matching Tailwind utility strings in `className`. Implement the AST traversal to flag these specific string patterns while allowing standard CSS Module variables (e.g., `styles.container`).
3. **[TDD] RFC 7807 Rule:** Write failing test cases for express/hono endpoints returning `res.status(400).json({ error: "bad" })`. Implement the AST traversal to ensure the response payload conforms to the `type`, `title`, `status`, `detail` structure.
4. **Integration:** Add the rules to the global `eslint.config.js` with `"error"` severity for relevant package globs.
5. **Verification:** Run `pnpm lint` across the workspace and fix any existing violations that the new rules uncover.
