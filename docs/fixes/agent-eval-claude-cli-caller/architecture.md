# Architecture: wire the weekly eval checkpoint to the claude-cli adapter, scored honestly

## Approach

The adapter that can run in the Friday sandbox exists (#5670); the fix is to make the only scheduled caller use it and to stop the scorer from failing every claude-cli task on a cost figure that is not money. Two shapes were compared. **Shape A — change the numbers:** raise every task's `maxCostUsd` until a claude-cli run fits. It loses because the budgets are shared with the billed SDK adapter (which would lose its $0.50 guard), and because the ~$1.37 floor is the repo's `CLAUDE.md`/rules/skills context being cached on turn 1, a property of the repo that grows with every rules edit, so any number chosen today is wrong by the next one. **Shape B — change what the number means (chosen):** the eval already knows cost is adapter-specific (`loadCostBaseline` is scoped per adapter since #4218; gemini's cost is structurally absent and passes the cost arm vacuously). Make that knowledge explicit as a `CostBasis` per adapter, apply the budget's cost arm only when the basis is `billed`, keep the reported figure in the row, and label the row so a reader knows $1.37 is API-equivalent. Around that core: the routine prompt names the adapter and treats exit 2 as a failure with a deduplicated issue; a small read-the-real-file test pins the invocation; the live trigger is updated last, by full-prompt replace and byte-diff. Nothing in the `auto` cascade, the default adapter, the SDK adapter, or key provisioning moves.

## Amendment 2026-09-29 — after Verify: the eval could not commit the agent's work, and lost the run

**What Verify measured** (verification.md § Criterion 1, § Failures F1–F3, assumption 10). The one authorized `--task example-bugfix --adapter claude-cli` run executed for real — 15 assistant turns on `claude-sonnet-5`, ~$0.60 API-equivalent, a 15-line test staged in the eval worktree in 66 s — and was then reported as a 0-turn non-run: exit 2, nothing persisted, and a `noRunMessage` blaming a missing binary or login. Re-read against source, the chain is: `WorktreePhase` creates a fresh `.agent-worktrees/` checkout (no `node_modules`, no `packages/agent-core/dist`) → `dispatch()` runs the CLI and returns real usage → `VerificationPhase.run()` (`phases/verification-phase.ts:39`) calls `worktreeManager.commitChanges()` → husky `pre-commit` → `check-adr --staged` imports the missing dist → `GitCommandError` (`run-git.ts`: `git commit -m … failed: …`, the exact logged text) → nothing in `VerificationPhase` or `runCliAdapterSession` catches, so `adapterResult` (15 turns, $0.60) and the `recordSpend` row are discarded → `runEvalSuite`'s catch → `failedScore()` hard-codes `costUsd: 0, turns: 0` → `taskDidNotRun` → `suiteDidNotRun` → exit 2 with a cause the message could not know. Two corrections to Verify's pins: the commit site is `VerificationPhase`, not `cli-adapter-base.ts:commitChanges()` (`runCliAdapterSession` calls `dispatch()`, which never commits); and had the commit succeeded, line 42 pushes the branch to `origin` with three retries, where `.husky/pre-push` fails closed in a fresh worktree on the same missing dist — a hook-free commit alone would have moved the failure one line down. Every step is adapter-independent and pre-existing: the SDK path shares `VerificationPhase`, and its own outer catch zeroes usage on a throw the same way. Assumption 10 (`verify()`'s checkout refused while the eval worktree holds the branch) is confirmed and sits one step further on; reading adds that the checkout, had it worked, would have switched the caller's own checkout to the agent branch.

**Approach of the amendment.** Two shapes were compared. **Shape C — make the eval worktree hook-capable** (install deps and build `@mbe/cli...` inside the worktree before the session commits): minutes per task, and it leaves the push and the pre-push hook needing the same build — it pays for the symptom at its most expensive point. **Shape D — treat the eval's session as what it is, a non-publishing session (chosen).** The commit hooks and the push exist to guard what reaches `origin` and `main`; a session with `createPr: false` publishes nothing, so it commits with git's own `--no-verify` and does not push (the post-commit gateway keeps running, unchanged, and every `createPr: true` path is byte-identical). The CLI session runner gains the outer catch its SDK sibling already has, so a throw after dispatch becomes a failed `SessionResult` that still carries the adapter's parsed usage and still writes its spend row. The eval scores that session as what it is — a row with real turns and cost, the session's own errors alongside, never a non-run — and verifies the fixture inside the kept worktree (`SessionResult.worktreePath`) instead of checking the branch out in the caller's repo. Around that core: `noRunMessage` claims only what it can distinguish, the drift guard pins the exact invocation, and the step-4 contract is amended in place with the same exit codes. Nothing in the `auto` cascade, the default adapter, key provisioning, or the `costBasis` design moves; the second Verify spend is exactly one run of `--task example-bugfix --adapter claude-cli`, and the last `assumptions:` entry states what it should produce.

The sections below carry the amendment where it lands; every amended item is marked **(amendment 2026-09-29)**. The pre-amendment design is otherwise intact and remains implemented (breakdown.md 8/8); Decompose adds the amendment's items to it.

## Decisions & alternatives

- **Per-adapter `CostBasis` with the cost arm applied only when `billed`** over _re-baselining `maxCostUsd`_ — budgets are shared with the billed SDK adapter, and the turn-1 context floor grows with every rules edit, so any number is re-broken later.
- Over _dropping `costUsd` for claude-cli in the parser_ (make it cost-blind like gemini) — throws away a real figure #5670 deliberately parsed and pinned in `claude-cli-adapter.test.ts`; loses the per-adapter cost trend `--max-cost-regression` already supports; `recordSpend` and `taskDidNotRun` would then lean on turns alone.
- Over _per-adapter budgets in task JSON_ (`maxCostUsdByAdapter`) — task definitions (policy) would import adapter names (detail), every new task needs N numbers, and the claude-cli number would still be a fiction.
- Over _forwarding `--max-budget-usd` to the CLI_ (the flag exists) — it would stop the agent at $0.50 of API-equivalent spend, i.e. right after loading context, guaranteeing task failure.
- Over _subtracting a measured context-overhead constant_ — a magic number that drifts with repo size and hides real cost movement.
- Over _an adapter-declared `costBasis` property on `AgentAdapter`_ — purer dependency direction, but `FailoverSessionAdapter` (`auto`) has no single answer, and it touches five adapter classes plus test doubles for a fact with exactly one consumer; the eval already keys adapter-specific knowledge by `AdapterType` (`noRunMessage`, `loadCostBaseline`). Revisit if a second consumer (e.g. `mbe agent run`'s budget gate) needs it.
- **Three basis values, not two** — `none` (gemini, no figure) and `api-equivalent` (claude-cli, real figure, not billed) collapse to the same budget behaviour but mean different things to a row's reader; the distinction costs one enum member and makes gemini's existing vacuous pass a named fact instead of an accident.
- **Exit-2 issue labelled `ci-fix` + `ready-for-human`** over _`ready`_ (would dispatch an implement-queue worker at an unfixable sandbox problem) and over _log-only_ (today's shape; the log is read weekly at best). Deterministic title without a date, comment on recurrence — `scheduled-workflow-health.mjs`'s convention, hand-executed by the prompt.
- **No `--threshold` this run** over _adding one_ — zero rows exist and the default suite has one task, so any value is a coin-flip policy; kept as an Operate seed.
- **Guard reads text, no imports** over _importing `VALID_ADAPTERS`_ — it is not exported and `tools/cli/dist` is not guaranteed in the scripts project; precedent says text.
- **Verify row not committed** over _committing it as the first baseline_ — different machine, different `~/.claude` context, and (see assumptions) possibly a harness-broken `testsPass`; the first Friday row is the honest baseline.
- **Live update = whole prompt, read back, byte-diff** — reconciles the brief's "resend full job_config" with `scheduled-tasks.md`'s field-scoped `update_trigger`; the invariant both protect is "never send a partial prompt, never trust a 200".
- **Adjacent surfaces deliberately left as-is** (each a seed candidate, none in scope): `run-cli-adapter-session.ts` still emits `session:budget_breach` on every claude-cli run (observe-only, `enforceBudget` defaults false); `recordSpend` ledgers the API-equivalent figure as spend under claude-cli, so `.claude/agent-spend/sessions.jsonl` over-counts; the excluded task still prints `score 33%`; `tools/cli/CLAUDE.md`'s `--adapter` list omits `claude-cli`; the `verify()` checkout-in-repoPath defect (fixed by the amendment below).
- **Amendment 2026-09-29 — non-publishing sessions (`createPr: false`) commit `--no-verify` and never push** over _building the worktree first_ (minutes per task; the pre-push hook needs the same build), over _`HUSKY=0`_ (env plumbing through `runGit`, hook-implementation-specific where `--no-verify` is git's own), over _`--no-verify` on the push too_ (keeps pushing a throwaway branch to GitHub on every eval — the 10 orphan `agent/*` refs on origin are that wart's litter), and over _dropping the commit for evals_ (`--no-pr` users inspect the commit; the branch is how a removed worktree's diff stays readable).
- **Reuse `createPr: false` as the non-publishing signal** over _a new `SessionConfig` field_ — in-file precedent (`pushPartialWork`, `abortOnFailure`, retention all gate on it), and no consumer of the pushed branch was found; the cost is one test title flipping, recorded.
- **Gateway unchanged for non-publishing sessions** over _skipping it_ — measured non-throwing without a key; skipping alters the SDK `--no-pr` result shape; the outer catch makes its worst case (amend → hooks) a scored failure row. Seeded: on the CLI path its verdict is consumed by nothing once PublishPhase skips, and `reviewDiff` fails open without a key.
- **Outer catch in `runCliAdapterSession`** over _teaching `failedScore` to read usage off a thrown error_ — the harness's catch is the last resort for a runner that threw before any result existed; usage belongs on the `SessionResult`, exactly as the SDK sibling does it. `failedScore`'s 0/0 is now the honest "no result exists" fallback.
- **`TaskScore.sessionErrors`** over _a closure-side map in the eval_ (the persisted row stays blind) and over _reusing `error`_ (would count a harness fault as "failed to complete").
- **`SessionResult.worktreePath`** over _parsing `git worktree list --porcelain`_ (full mode only, a parser in the CLI) and over _deriving from the `.agent-worktrees/<branch>` layout_ (couples the eval to worktree-manager's private naming).
- **Verify inside the kept worktree** over _fixing the `repoPath` checkout_ (it would still switch the caller's checkout to the agent branch and require the commit to exist) and over _a second clone per task_ (a full clone of this monorepo per eval task).
- **G1 resolution (Architect re-entry 2026-09-29): fixture scripts run through `pnpm turbo run <script> --filter=./<fixtureRef>`** over _`pnpm --filter ./<fixtureRef> <script>` as first designed_ (measured: 46 of 111 reservations test files fail on an unbuilt `@mbe/types`/`@mbe/api-client` dist — `testsPass: false` for harness reasons on every row), over _an explicit `pnpm turbo run build --filter=./<fixtureRef>^...` step with its own bound_ (the same builds, a second bound and a second copy of the dependency set the task graph already declares), and over _accepting the harness `false` and correcting the second-spend expectation_ (it is the exact outcome the verifier's deletion test says it exists to prevent). Cost: the first script per task pays ~45–70 s of workspace builds, hence the 600 s bound.
