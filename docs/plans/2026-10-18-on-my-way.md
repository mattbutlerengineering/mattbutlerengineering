# On My Way — feasibility check + build plan

> **Status: future plan — unblocked, not yet filed.** Needs no venue history, no LLM key, and no external accounts. Nothing here is filed as an issue; run `/decompose` on this file to start it. File references verified against `main` at `b23bec446`, 2026-10-18.

## Context

"Are they still coming?" is the host's question every night. Today a late party calls — if they call — and the table either sits empty or is given away by mistake.

On My Way: on the day of the booking, the guest's link becomes a live **night-of page** — countdown, party summary, one-tap directions, the venue's note for tonight ("Patio's open, dress warm") — with two big buttons:

- **"Running 15 min late"** → the host's screen instantly shows the table held with an amber "+15" badge and ETA; the timeline bar shifts.
- **"We're here"** → a chime and the party name at the host stand before they reach it.

Tap on the phone, badge on the iPad within the second — the guest half of the Host Stand (#7055) demo. Wallet Pass (#7056) and The Invitation (#7053) link to it; Brand Match (#7048) styles it; The Marquee (#7054) supplies the venue note. Matt loved it (2026-10-18).

## Approach

### 1. Guest signal routes

`POST .../manage/signal` `{ kind: "running-late", minutes: 5 | 15 | 30 } | { kind: "arrived" }`, authenticated by the manage token exactly like cancel/modify, behind `guardManageState`. Rules (pure `canSignal(reservation, now, priorSignals)`, unit-tested): only on the reservation's date, from T-3h to T+45m; confirmed reservations only; max 3 late signals, 1 arrived; per-token rate limit. Persists a `ReservationEvent` (`kind: "guest-signal"`, `actorType: "guest"`). **Never mutates the booking** — no time change, no status change; it's information for staff.

### 2. Realtime event

`reservation:guest-signal` `{ reservationId, kind, minutes?, eta? }` emitted through `services/events.ts`, venue-scoped; add to `hooks/sse-query-keys.ts` so staff queries refresh.

### 3. Staff UI

- Amber "+15 · ETA 7:45" badge on the `TimelineGrid` bar and the `FloorPlanCanvas` table; table shown held through the ETA.
- "Arrived" chime (respect a mute setting) + toast with party name and size.
- Badge clears when the party is seated or the reservation changes.

### 4. Night-of page state

`ManageReservationPage` switches to night-of layout on the reservation date (venue timezone): countdown, party/time, "Get directions" deep link (address from The Marquee profile if present, else venue name search), tonight note (`Venue.settings.tonightNote`, ≤200 chars, owner-editable from the dashboard), the two signal buttons with confirmation feedback. Strings in `en-US.json` / `fr-CA.json` / `es-MX.json`.

### 5. SMS keyword (optional, later)

Reply "LATE 15" / "HERE" to the reminder SMS via the existing Twilio integration — needs an inbound webhook with Twilio signature verification.

## Risks

- **Abuse/spam** → token required, time window, signal caps, rate limit; signals never change the booking.
- **Manage-token exposure**: the manage token is signed but not encrypted and carries the booker's email (found during The Invitation plan). This feature adds no new exposure but more traffic through it — consider fixing the token format first.
- **Timezone edges** → "is it the reservation day" computed in the venue's `ianaTimezone`, tested across DST and midnight.
- **Alert fatigue at the stand** → chime is mutable; badges are quiet.
