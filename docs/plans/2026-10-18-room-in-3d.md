## Approach

### 1. Pure scene mapper — `components/room-3d/layout-to-3d.ts`

`layoutTo3D(layout, tables) → SceneDescription`: 2D canvas px → world units (1 grid = fixed metres), rotation in radians, tabletop dimensions per shape, **chair placement by `capacity`** around each shape (rect: long sides first; circle: evenly spaced), floor + perimeter walls from layout bounds. Pure, no three.js import — unit-tested heavily.

### 2. `Room3D` component (lazy chunk)

`lazy(() => import("./Room3D"))`; renders `SceneDescription` with a low-poly instanced kit (one table geometry per shape, one chair geometry, `InstancedMesh`). Constrained orbit (no under-floor, min/max zoom). Clicking a table calls the same `onTableSelect(id)` the 2D canvas uses.

### 3. Lighting presets

`day` (soft directional + ambient) and `evening` (low ambient, warm point light over each table, gentle bloom-free glow). Colours from rialto tokens. Shadows only on capable devices.

### 4. Live status

Accepts the same `tableStatuses: ReadonlyMap<string, TableDisplayStatus>` as `FloorPlanCanvas`, tinting tabletops via `TABLE_STATUS_COLOR_TOKEN` — so Dress Rehearsal and Host Stand drive it with no extra wiring.

### 5. Toggle + fallbacks

2D/3D toggle in `FloorPlanEditorPage` and the onboarding reveal. Fallback to 2D when WebGL is unavailable or context is lost. `prefers-reduced-motion` → no auto-rotate, no animated light transitions. DPR capped (≤1.5), frame-loop `demand` (render only on change).

### Later (out of scope v1)

3D in the public booking widget (guest side), walls/doors/bar from a richer layout model, photo textures.

## Risks

- **Bundle weight** (three.js is large) → lazy chunk only, never in the widget/dashboard entry; add a `size-limit` entry for the new vendor chunk (the vendor-chunk coverage check will otherwise fail `size:check`); run `/perf-budget`.
- **Low-end devices** → instancing, DPR cap, demand frame-loop, shadows off by default on mobile, 2D fallback.
- **Accessibility** → 3D is decorative; the 2D canvas keeps keyboard/screen-reader parity and stays the editing surface. Toggle is a real button with state.
- **Value on its own is visual** → best built after Dress Rehearsal / Choose Your Table so it amplifies something.
