## Design gaps found

- **The architecture's W2 group ships a broken wizard to production.** W2 bundles `onboarding-steps.ts` + `TOTAL_STEPS = 6` with the reducer, three merges ahead of W5, which is what renders steps 5 and 6. In between, `main` deploys a six-entry rail whose step 5 is the Launch review mislabelled `Floor plan` and whose step 6 is an empty card. Not routed back to Architect because it is a sequencing fault, not a design one: the fix is entirely within Decompose's remit — the count flip moves into item #9 and item #5 stays additive and inert. Recorded so the reviewer sees the W2 group was deliberately not implemented as written.
- **`DEFAULT_LAYOUT` gains a second definition.** M7 requires the created plan's `layoutJson` to equal what `NewFloorPlanDialog.tsx:9-14` sends, and that constant is module-private in a file the architecture freezes. Item #3 re-derives an identical literal from the same `floor-plan-geometry` constants and pins it with a test. The real fix — hoisting `DEFAULT_LAYOUT` into `floor-plan-geometry.ts` and having both consumers import it — needs the frozen file touched and is not designed around here. Backlog candidate at Operate.
- **`DraftTable.localId` has no specified generator.** The architecture names the field and its lifetime ("draft-only, never sent") but never says who mints it or whether it must survive a rename. Resolved by assumption (`localId = name` at every producer) rather than by inventing a counter or a random id, both of which would make the reducer impure or non-deterministic. Noted in #4752 so the reviewer sees it was a choice.
- **`LaunchStep`'s new props cannot be required.** The architecture orders W4 (LaunchStep) before W5 (the page), which makes a required new prop a typecheck failure inside W4's own PR. Item #8 defaults all three; item #9's acceptance includes actually passing them, so the defaults cannot quietly become the shipped behaviour.
- **Two doc paths in `architecture.md` do not resolve.** `docs/USER-FLOWS.md` and `docs/IMPROVEMENT-BACKLOG.md` are actually `apps/hospitality/docs/USER-FLOWS.md` and `apps/hospitality/docs/IMPROVEMENT-BACKLOG.md`. Corrected in #4763 rather than silently followed.
- **PRD M3 and the architecture disagree on where `floor-plan-templates.test.ts` lives** (`components/floor-plan/` vs `components/venue-onboarding/`). The architecture wins — the templates are onboarding's, and the editor never reads them.
