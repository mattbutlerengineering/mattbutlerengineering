## Method and limits

- **Harness** (git-excluded in the run worktree, `apps/hospitality/e2e/.ux-audit/`):
  `gen-state.mjs` writes an unsigned OIDC session in the exact localStorage
  shape `e2e/auth-helpers.ts` `buildOidcUserEntry()` produces (admin
  permissions); `playwright.config.ts` + `specs/walk.spec.ts` walk 17 routes at
  1440×900 / 1024×768 / 390×844 in light and dark, capturing screenshots,
  an aria snapshot, headings, landmarks, buttons, console errors and failed
  requests per route; `specs/<report>/*.spec.ts` are the interaction probes.
  API traffic is served by the E2E suite's own `mockApi(page)` fixtures
  (`e2e/api-mocks.ts`, venue `e2e-test-bistro`); `VITE_API_URL` points at a
  dead port so nothing unmocked can reach production.
- **Live production** was probed only for the unauthenticated surfaces
  (`/hospitality/book/<slug>`, `/hospitality/reservations/manage`, the
  `/public/v1/*` API path). The authenticated dashboard has **zero production
  evidence** in this audit — no Auth0 E2E credentials exist in this
  environment (on Matt since 2026-08-31). Every dashboard finding is
  reproduced against fixture data at the audited commit; none is a guess.
- **Excluded as harness artifacts, not findings:** `GET /api/health/system`
  and the SSE stream refused (dead port); `/api/v1/briefing` and
  `/table-statuses` unmocked by default; `todayReservations()` in
  `api-mocks.ts` re-dates fixtures with the UTC day (so after 17:00 PDT the
  shared mock renders an empty timeline — the same defect class as findings
  A1/A2, in the test mock rather than the product; seeded to the backlog);
  the waitlist `GET` mock only returns `waiting` rows; the tables mock is not
  stateful.
- **Not reached:** SSE reconnect states beyond the banner; floor-plan drag
  and Activate-failure paths; live updates on the dashboard; the deposit
  Payment step (see C3); `NeonSign` (excluded per #4746); Auth0 login page
  (#4848 / PR #4924).
- **Screenshots and probe JSON** live in the session scratchpad
  (`scratchpad/ux-audit/out/<report>/`), which is ephemeral. The reports
  quote every number they rely on, so the evidence survives in `audit/*.md`.

## Consolidated findings (deduped, ranked by leverage)

Leverage = impact × reach ÷ effort, reproduced before suspicion, correctness
before polish, the product's core screen (Timeline, per `PRODUCT.md` theme 2)
before peripheral pages. Effort S < 1 day, M 1–3 days. IDs are stable for
routing; `Source` names the report IDs that were merged.

### Suspicions (not reproduced — do not file as findings)

- Escape-path focus loss on the hand-rolled dialogs may be StrictMode-only (double effect re-captures `activeElement` after the trap moved it); success paths and rialto `Drawer` do not depend on it.
- "Live" pill reads Live while the SSE stream is dead — indicator source not traced.
- Waitlist Notify may drop the guest from the list (shared mock filter is the proven cause; real `GET` not verified); waitlist seat gives no handoff to the timeline block it created.
- Walk-in default table ignores current table status (an OCCUPIED/DIRTY table can be the default).
- Late-evening walk-ins may be stamped with tomorrow's `date` by the service serializer (UTC `toDateString` on a `@db.Date`).
- `ErrorRetryBanner onDismiss={() => {}}` on Floor Plans: rialto `Alert` self-hides, removing the only Retry while the query stays errored.
- `SetupHoursPage` seeds `useState` from `selectedVenue` once — stale hours on venue switch once E1 makes it reachable.
- Guest email travels in a GET query string to a public endpoint; embed "frame" is a `div`, not an `iframe`.
