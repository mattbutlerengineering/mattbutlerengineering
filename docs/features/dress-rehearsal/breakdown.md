## Notes

- 2026-10-19 UX amendment (not applied to ux.md): UX Screen 2's legend lists a distinct "ready" table status, but `TableDisplayStatus` has only `available`, `seated`, `needs-bussing`, `reserved-soon`. Decision: the simulator keeps occupied, dirty, ready, available internally and the view model maps ready to available, so the floor plan legend shows available, occupied (seated), dirty (needs-bussing) and no "ready" entry. The alternative, extending the shared type, was rejected as a cross-app change for a throwaway view. Verify and Review should read ux.md Screen 2 with this amendment. Revisit if owners find a table that is clean but not yet seatable confusing.
- 2026-10-19 Ordering deviations from the plan's list: shared readOnly changes precede the workspace; the guard test sits in Milestone 1; a minimal empty-night entry sits in Milestone 1 so the demo is reachable.
- 2026-10-19 Implement deviations (items 1-2): the `seated` event carries `size` and `endAt` (walk-ins have no `booked` event, so the reducer needs them); `rehearsalMetrics(events, tableIds)` takes the table ids because tables that never appear in an event cannot otherwise be reported as never sat; `rehearsalStateAt` takes an optional third `closeMinute` clamp; `eventIndexAt` and `foldEvents` are exported so the playback hook can memoize the fold on `eventIndex`. Peak hour = hour of day with the most covers seated (ties earliest). Walk-in-waiting is emitted only for walk-ins who wait at least a minute. `avgTurnMinutes`/`peakHour` are `null` when nobody was seated.
- 2026-10-19 Implement deviation (item 4): read-only blocks are `div role="group"` with the same aria-label rather than the HTML `inert` attribute, because `inert` would hide the simulated bookings from assistive tech, which the UX names the accessible equivalent of the canvas. They are non-focusable and carry no click, so the acceptance intent (no action reachable) holds.
- 2026-10-19 Implement notes (item 6): `useRehearsalPlayback` gained an optional `onTick(minute, ts)` so the workspace can run the live-region throttle without effects; `shouldAnnounce` lives in `should-announce.ts`. Catalogs: `check-i18n-catalogs` requires es-MX as well as fr-CA, so every `rehearsal.*` key lands in en-US, fr-CA and es-MX together (en-GB falls back). "Right now" is two whole sentences (tables occupied, parties waiting), each pluralised on its own count, instead of one two-count sentence i18next cannot pluralise. The Floor plan canvas sits in an `inert` wrapper under `role=img`, so its keyboard overlay buttons are not tab stops. The curtain-call live message (`Service is over...`) lands with the Curtain call item.
- 2026-10-19 Implement notes (item 7): DashboardLayout reachability CONFIRMED (not a design gap): `/rehearsal` is not in `OPERATIONAL_ONLY_PATHS` and the layout only bounces `/setup` and `/`, so both an operational and a setup venue render the workspace (`RehearsalPage.route.test.tsx`). `layout.routes.rehearsal` was added to DashboardLayout's `ROUTE_LABEL_KEYS` so the document title and breadcrumb read Rehearsal instead of the generic Details fallback. `@mbe/sentry/react` exposes no generic captureException, so the simulator failure is reported through `handleErrorBoundary(error, { componentStack })`, the module's existing error path.
