# Real-Time Updates Evaluation — February 2026

## Current State

| Dimension | Value |
|-----------|-------|
| **Real-time** | None — dashboard polls or manually refreshes |
| **WebSocket support** | Not implemented (Fastify supports it via `@fastify/websocket`) |
| **Use case** | Host/staff see reservations appear and update in real time |

### Use Cases

1. **Live reservation board** — new bookings, cancellations, and status changes appear instantly for host staff
2. **Hold countdown** — visual countdown of `holdDurationMinutes` on the dashboard
3. **Table status updates** — seated, available, cleaning status changes in real time
4. **Future: Guest notifications** — "your table is ready" push to guest's browser

### Traffic Profile

This is **low-frequency, low-volume** real-time. A busy restaurant might see 1-2 reservation events per minute during peak hours. This is not a chat app or trading platform — it's a handful of events per minute to a handful of connected dashboard users.

## Approach Comparison

### 1. Server-Sent Events (SSE) — Recommended

Unidirectional server-to-client streaming over HTTP. Built into browsers. No library needed on the client.

| Criterion | Details |
|-----------|---------|
| **Direction** | Server → Client only |
| **Protocol** | HTTP (standard, works through proxies/CDNs) |
| **Client** | Native `EventSource` API (all browsers) |
| **Server** | Fastify route that streams text/event-stream |
| **Reconnection** | Automatic (built into EventSource spec) |
| **Library needed** | None (client); minimal (server) |
| **Cost** | $0 — part of your existing Fastify server |
| **Scalability limit** | Number of open HTTP connections per server instance |

**Key strength for this project:** The use case is unidirectional — the server pushes reservation events to connected dashboards. The client doesn't need to send data over the real-time channel (it uses REST API for actions). SSE is the simplest solution for unidirectional push:

```typescript
// Server (Fastify)
fastify.get("/api/v1/venues/:venueId/events", (request, reply) => {
  reply.raw.writeHead(200, {
    "Content-Type": "text/event-stream",
    "Cache-Control": "no-cache",
    Connection: "keep-alive",
  });

  const handler = (event: ReservationEvent) => {
    reply.raw.write(`data: ${JSON.stringify(event)}\n\n`);
  };

  eventBus.on(venueId, handler);
  request.raw.on("close", () => eventBus.off(venueId, handler));
});

// Client (React)
const source = new EventSource(`/api/v1/venues/${venueId}/events`);
source.onmessage = (event) => updateReservationBoard(JSON.parse(event.data));
```

### 2. WebSockets (via @fastify/websocket)

Bidirectional communication. More powerful than SSE but more complex.

| Criterion | Details |
|-----------|---------|
| **Direction** | Bidirectional |
| **Protocol** | WS/WSS (upgrade from HTTP) |
| **Client** | Native `WebSocket` API or libraries |
| **Server** | `@fastify/websocket` plugin (built on `ws`) |
| **Reconnection** | Manual (must implement yourself) |
| **Cost** | $0 — part of your existing Fastify server |

**When to prefer over SSE:** When the client needs to send real-time data to the server (e.g., collaborative editing, chat). For reservation board updates, the client reads events and takes actions via REST — WebSockets add complexity without benefit.

---

### 3. Pusher

Managed real-time infrastructure as a service.

| Criterion | Details |
|-----------|---------|
| **Free tier** | 200 concurrent connections, 200K messages/day |
| **Paid** | $49/month (500 connections) |
| **SDK** | `pusher` (server) + `pusher-js` (client) |

**Elimination reason:** $49/month for something SSE does for $0. The free tier is generous (200 connections) but adding a vendor dependency and two SDKs for a few events per minute is over-engineering. Pusher makes sense for chat apps with thousands of concurrent users, not a restaurant dashboard with 2-5 staff connections.

---

### 4. Ably

Enterprise-grade real-time platform.

| Criterion | Details |
|-----------|---------|
| **Free tier** | 200 connections, 6M messages/month |
| **Paid** | $29/month |

**Elimination reason:** Same as Pusher — paying for a managed service when SSE is free and sufficient.

---

## Recommendation: Server-Sent Events (SSE)

| Dimension | Details |
|-----------|---------|
| **Cost** | $0 |
| **Dependencies** | None (native browser API + Fastify) |
| **Complexity** | Minimal — ~30 lines of server code |
| **Scalability** | Sufficient for dozens of concurrent dashboard connections per venue |
| **Fallback** | If SSE ever becomes insufficient, upgrade to WebSockets (same server, similar API) or add Pusher/Ably |

**When to reconsider:** If the project needs bidirectional real-time (collaborative table assignment, live chat with guests) or if DigitalOcean App Platform's connection limits become a bottleneck. At that point, WebSockets via `@fastify/websocket` is the first upgrade, not a managed service.
