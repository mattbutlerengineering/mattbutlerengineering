# Caching Layer Evaluation — February 2026

## Current State

| Dimension           | Value                                  |
| ------------------- | -------------------------------------- |
| **Caching**         | None (every API request hits Postgres) |
| **Rate limiting**   | None                                   |
| **Session storage** | Auth0 (external, managed)              |
| **Redis/Valkey**    | Not present in stack                   |

### Why This Matters

1. **BullMQ requires Redis** — the Background Jobs evaluation recommends BullMQ, which needs Redis. Adding Redis for jobs makes it available for caching at zero marginal cost.
2. **API response caching** — availability queries (open time slots) are read-heavy and time-bounded; perfect for short-lived cache.
3. **Rate limiting** — API endpoints need rate limiting before production (OWASP requirement).
4. **Session/token caching** — Auth0 JWKS key caching, API response memoization.

## The Redis Question: Which Redis?

Redis changed its license to dual SSPL/RSALv2 in March 2024, then added AGPLv3 in May 2025. This fragmented the ecosystem:

| Engine            | License                | Compatibility             | Notes                                                        |
| ----------------- | ---------------------- | ------------------------- | ------------------------------------------------------------ |
| **Redis** (v8+)   | SSPL + RSALv2 + AGPLv3 | The original              | AGPLv3 added for open-source users; SSPL/RSAL for commercial |
| **Valkey** (v8.1) | BSD 3-Clause           | Drop-in Redis replacement | Linux Foundation fork; supported by AWS, Google, Oracle      |
| **Dragonfly**     | BSL 1.1                | Redis-compatible          | 25x faster benchmarks; multithreaded                         |

**For this project:** The engine doesn't matter at this scale. BullMQ works with all three. The choice is really about the managed service, not the engine.

## Managed Redis Services

### 1. Upstash Redis (Recommended)

Serverless Redis. Pay per request. $0 free tier.

| Criterion         | Details                                       |
| ----------------- | --------------------------------------------- |
| **Free tier**     | 10,000 requests/day, 256 MB storage           |
| **Pay-as-you-go** | $0.20/100K requests + $0.25/GB storage        |
| **Regions**       | Global (AWS/GCP regions)                      |
| **Protocol**      | Redis-compatible + HTTP REST API              |
| **BullMQ**        | Officially supported (documented integration) |
| **TLS**           | Included                                      |
| **Persistence**   | Durable (replicated storage)                  |
| **Serverless**    | Yes — no server to manage, scales to zero     |

**Key strength:** Perfect for solo developer. $0 free tier covers development and low-traffic production. No server to manage. Scales automatically. BullMQ integration is documented and tested.

**Free tier math:** 10,000 requests/day = 300,000/month. A reservation system doing 100 bookings/day with BullMQ + caching + rate limiting is well within this.

---

### 2. DigitalOcean Managed Redis

Traditional managed Redis on DigitalOcean (where the project hosts).

| Criterion       | Details                       |
| --------------- | ----------------------------- |
| **Pricing**     | $15/month (1 GB, single node) |
| **Free tier**   | None                          |
| **Regions**     | DigitalOcean data centers     |
| **BullMQ**      | Works (standard Redis)        |
| **Persistence** | Configurable (RDB/AOF)        |

**When to choose over Upstash:** If you need guaranteed low-latency in the same data center as your DigitalOcean App Platform services. At $15/month, this is the "production-grade" option when cost isn't the primary concern.

---

### 3. Docker Compose (Local Development)

Redis in Docker for development. Already have Docker Compose for Postgres.

| Criterion | Details                                               |
| --------- | ----------------------------------------------------- |
| **Cost**  | $0                                                    |
| **Setup** | Add `redis:7-alpine` to existing `docker-compose.yml` |

```yaml
redis:
  image: redis:7-alpine
  ports:
    - "6379:6379"
```

---

## Recommendation: Upstash Redis (production) + Docker Redis (local)

| Environment       | Provider                          | Cost                                       |
| ----------------- | --------------------------------- | ------------------------------------------ |
| **Local dev**     | Docker Compose (`redis:7-alpine`) | $0                                         |
| **Production**    | Upstash Redis (serverless)        | $0 (free tier)                             |
| **Scale trigger** | DigitalOcean Managed Redis        | $15/month (when free tier is insufficient) |

This gives you Redis for BullMQ (background jobs), API caching, and rate limiting — all at $0/month. The same Redis instance serves all three use cases.
